# 短剧前期：一句话 → 标签 → 概念 → 整季 → 逐集大纲 / 剧本 / 分镜

和网页版「短剧创作台」是同一套流程和同一套质量门，适合在 Claude 对话或 Claude Code 里用、产出直接存成文件。与用户交流用中文。

方法来源：编剧方法取自 screenwriting-skills（MIT，Snyder / McKee / Cron / 陆军 / 姚扣根等），质量门与分镜写法取自 shuohao-skills（Apache-2.0），概念发散参考 MoPS 模块化前提和「先发散再收敛」。本技能自包含。

## 两种模式

- **逐步模式（默认）**：一次只做一个阶段 → 跑质量门 → 停下等用户确认，确认前不开始下一阶段。
- **自动模式**（用户说「自动」「一口气写完」「写到第 N 集」时）：每阶段生成 → 质量门 → 没过就按失败条目修，最多 3 轮 → 剧本再按「审片打分」评分，低于及格线（默认 75）按改法重写一次 → 进入下一阶段 / 下一集。只在两处停：挑概念、整季写好。修了 3 轮仍没过的，记进 state.md 继续往下，最后一并汇报。

## 项目目录

```
<剧名>/
  0-项目卡.md       灵感输入台导出的项目卡，原样保存（有的话）
  1-cast.md         人设卡（读项目卡产出）
  state.md          阶段｜文件｜状态（待做 / 待确认 / 已确认 / 需重审）｜一句话摘要；另记保留牌、弃牌、口味
  0-tags.md
  1-concept.md      选定概念
  1-deck.md         牌库：保留的概念卡和弃掉的概念标题
  2-season.md       整季圣经
  E01/outline.md  E01/script.md  E01/shots.csv  E01/review.md
```

每次开工先读 state.md，从第一个未确认的阶段继续。

## 省 token 规则

1. 每阶段只读直接上游。逐集写时只读：整季人物表、主线、本集和下一集的分集行、前两集的梗概。不重读聊天历史。
2. 长内容写进文件，聊天里只给三到五句摘要和需要拍板的问题（最多 3 个选项并标推荐）。
3. 修改只动受影响的部分。上游改了，下游已确认阶段标「需重审」，只重做受影响的部分。
4. 能用脚本查的不靠自觉：剧本和分镜写完必须跑 `python3 .claude/skills/short-drama-preprod/scripts/check.py`，有 ✗ 逐条修到全过。

## 阶段 0A　输入审（默认，替代标签和概念抽卡）

原则：记忆点由人写，AI 只提问、找俗套、给对标，不改写用户的句子。依据见 `docs/research/AI拉平与输入设计-2026-10.md`。产出 `0-input.md`。

1. **一句话**：用户自己写。AI 先做两句体检（哪里清楚、哪里换成别的剧也成立），再用 5 个固定问题追问：主角是谁、她最反差的一点、她最想要什么、谁挡着她、观众第一眼看到什么画面。用户卡住时，每个问题最多给 3 个启发例子，标明「别照抄，改成你的」。
2. **找俗套**：列这类故事最常见的 5 种写法；指出用户句子里的通用部分和原因；用户自己改写一句话。
3. **钉子**：用户写 3–5 个记忆点（画面、台词、规则、人设怪癖）。AI 逐个体检：1–5 分的独特度、一句判断、一个让它更尖的问题。之后所有阶段必须原样保留钉子，审片时检查。
4. **标签最多 3 个**：AI 给 3 组，每组 3 个标签并附一部真实上榜对标剧（只能从调研里列出的剧名里选），用户选一组或自己写。

⛔ 关卡：用户确认 0-input.md。之后再进整季或切片。

## 切片模式（AI 短剧常见的碎片化看法）

观众常常只看切片：一段 15–45 秒、能单独看懂的心动或爽点名场面，集与集之间不必紧密连贯。切片模式下跳过整季，产出 `clips/`：
- `clips/index.md`：人物卡（姓名、一句人设、固定 look）、规则（能力或设定的限制）、切片清单（每条：标题、用到的钉子、场景、情绪顶点）。
- `clips/C01.md`：剧本格式同阶段 4，标题写「# C01 标题 目标 N 秒」，N 在 15–45 之间。要求：第 1 秒就有画面钩子；只有 1 个情绪顶点（心动、爽、笑）；至少用 1 个钉子且一字不改；结尾停在情绪最高处或一个小悬念；同框不超过 2–3 人，靠颜值、氛围和动作说话，台词每句不超过 15 字。
- 质量门照常跑 `check.py script`；审片看三件事：钉子在不在、单看懂不懂、想不想转发。

## 模块交接（四块，各一进一出）

整部剧拆成四块分开做，每块只读上一块的文件，写出自己的文件，再拼回同一个剧文件夹。哪块出问题只重做那块，下游标「需重审」。

| 块 | 读 | 写 | 谁做 |
|---|---|---|---|
| 1 灵感 | 用户在网页输入台点选 | `0-项目卡.md` | 用户 + 网页 `studio/input-desk.html` |
| 2 人设 | `0-项目卡.md`「角色」「世界和规则」 | `1-cast.md` | screenwriter |
| 3 剧本 | `0-项目卡.md` + `1-cast.md` | `2-season.md`（或 `clips/`）、`E0n/script.md` | screenwriter → 审片人 |
| 4 分镜 | `E0n/script.md` + `1-cast.md` 的 look | `E0n/shots.csv` | storyboarder（用户要时才做） |

交接规则：
- 项目卡原样保存，不改写；其中注明「作者亲手写」的台词，所有下游原样保留，审片检查。
- `1-cast.md` 每个角色一段：姓名、一句人设、性格、固定英文 look（沿用项目卡里的 look 并补全发型、服装、标志物），下游逐字复用 look，防止变脸。人设卡做完停下等用户确认。
- 项目卡里已有的名场面切片直接进 `clips/`（编号保留），剧本块从这些切片长出整季或更多切片，不推翻。

## 阶段 0　标签（0-tags.md）（旧流程，用户要求时才用）

按 7 组给点子挑「想要」和「避开」：世界/题材、女主人设、男主人设、关系/情感线、金手指/设定钩子、爽点/情绪、调性/结局。每组 0–2 个，总数 5–9 个；优先能制造反差和新鲜感的组合；避开 2–4 个在这个点子上最容易写俗的标签；可加 1–3 个自定义标签。让用户增删后确认。

## 阶段 1　概念抽卡（1-concept.md、1-deck.md）

**内部方法（不输出过程）**：按「世界 → 主角处境 → 关系 → 设定钩子 → 爽点 → 结局 → 反转」七个模块组合出 10 个差异很大的前提；对每个问「是不是这些标签最常见的写法」，是就把一个模块反过来（强者其实被保护、甜宠契约其实是陷阱）；删掉最俗的 7 个，给 3 张卡。用户已有完整设定时可只提炼 1 张并指出最弱两项。

每张卡：片名、类型标签、一句话故事（Snyder：反讽钩子 + 能脑补的画面，主角和反派各带一个形容词）、Logline（Hoxter：主人公 + 激发事件 + 挑战 + 赌注 + 主题）、新鲜点（和最常见写法比新在哪）、开场画面（前 10 秒看到什么）、渴望与错误信念（Cron，结局如何被打破）、戏核（陆军：抽掉后戏就不成立的动作、道具、境遇或一句话）、核心反差，以及 8 维分（1–10，要诚实：钩子强度、反差、新鲜度、情绪价值、人设标签、系列化、AI 可制作性、合规；常见套路的新鲜度不超过 6）和最弱两项。

**抽卡**：用户可以「保留」「弃掉」「再抽」。再抽时把保留的当口味参照但不重复、弃掉的那类避开、之前出现过的方向不再给；默认两张贴口味、一张故意出意外。保留加弃掉满 3 张后可以总结口味（喜欢、不喜欢、可能会喜欢的新方向）。用户要合并时：选一张做骨架，其余只取能放大骨架的零件，不平均拼贴，合并后仍要一句话说得清。

⛔ 关卡：用户选定一张。

## 阶段 2　整季（2-season.md）

```
# 片名 共 N 集 每集 60 秒
## 人物
C01｜姓名｜年龄｜标签｜渴望：…｜秘密：…｜说话方式：…｜look: English appearance description
## 主线
## 分幕
第一幕 E01–E10｜这一幕做什么
## 分集
E01｜本集标题｜本集主事件｜结尾钩子 #反转
```

- 人物表是全季圣经：姓名、年龄、标签、look 一旦定下，之后每集逐字复用；look 写固定主造型（发型、发色、脸部特征、主服装），方便 AI 画面保持一致。主要人物 3–6 个，后期关键配角也进表。
- 分幕 3–5 幕；分集每集一行，一集只推进一件事，必须有状态变化（关系、身份、处境）；结尾钩子让人想点下一集。
- 每 3–5 集至少一个 #反转；N ≥ 10 时设 #卡点（付费点）：N < 40 放在约 25–35% 处，N ≥ 40 放在约 10–18% 处，之后每 10–15 集一个；主线和感情线交替，不能连续 3 集只走一条线。
- 全季最大爆点不放在最后一集；后期才发力的核心人物第 1–2 集露脸；全季主场景不超过 4 + ⌈N / 10⌉ 个；最后一集收束主线，可留续季钩子。
- N > 30 时先写 30 行，再每次续写 30 行。

整季检查：集数正好 N、集号连续、每集有事件和结尾钩子、每人有 look、连续不超过 5 集没有反转或卡点、N ≥ 10 时有卡点。

⛔ 关卡：用户确认整季。只写一集时跳过本阶段。

## 阶段 3　逐集大纲（E0n/outline.md）

输入：整季人物表、主线、本集和下一集的分集行、前两集的梗概（第一集则要求前 10 秒立住人设和核心冲突）。

```
## 角色      （只列本集出场的人，逐字沿用圣经）
## 场景      S01｜场景名 · 日/夜
## 节拍      0:00｜节拍内容｜钩子
## 拍板      砍掉：… / 合并：… / 最大爆点：…（落在几分几秒）
## 梗概      叙述体，不写引号对白
```

- 节拍类型只用：钩子、压迫、打脸、爽点、甜点、心动、反转、悬念。第一拍是钩子（0:00），之后每 10–20 秒一个拐点，最后一拍是悬念，不超出片长。
- 单集主角组 ≤3 人（120 秒以上 ≤5），主场景 ≤5 个。
- 类型含甜宠时，每集至少 1 个甜点或心动拍，甜落在具体动作上。
- 结构自检（陆军）：入戏快（起点近、焦点单、疑点少）；高潮不早、不滑、不靠下跪耳光；转变不靠搬救兵；结尾不圆、不拖、不跳、不软；每个拐点让局面变一次，优先由人物性格和选择引起。

⛔ 关卡：把拍板三件事摆给用户。

## 阶段 4　剧本（E0n/script.md）

剧本管戏，分镜管拍：没有镜号和提示词。格式（质量门靠它解析）：

```
# E01 本集标题 目标 60 秒
## S01 内景 · 学院走廊 · 夜 ｜ 人物：许眠, 霍凛
1. [动作] 霍凛把许眠抵在墙上，眼睛泛起银光 #钩子
2. [台词] 霍凛｜压低、危险｜你对我做了什么？
```

- 节拍按集连续编号；[动作] 和 [台词] 尽量交替；台词写「说话人｜语气｜台词」，内心独白写「姓名（内心）」，旁白写「旁白」；标签只用 #钩子 #爽点 #甜点 #反转 #悬念。
- 动作只写 AI 见过千万次的常见动作（抬头、转身、伸手、靠近、坐下），情绪用身体外化，不写精细动作和形容词情绪。
- 对白（McKee / 陆军）：每句有动作意图；遮住人名也能分辨谁在说；不说两人都知道的事；不把潜台词说出来；能用动作代替的就删。
- 场结构（Miller）：每场一个主角，想要什么、阻碍、至少三次升级、一个决定、一个结果；每场至少一个动作节拍。
- 时长按台词 4.5 字/秒、动作 2.5 秒/拍估算，必须在目标 ±15% 内。实测第一稿常常写短，先估算再交。

运行 `python3 .claude/skills/short-drama-preprod/scripts/check.py script <剧名>/E01/script.md`，有 ✗ 逐条修。

**审片打分（E0n/review.md）**：按竖屏短剧标准给 1–10 分并加权（满分 100）：前 3 秒钩子 20、冲突与爽点密度 20、人设标签 10、情绪价值 15（类型该有的情绪，甜宠要甜）、集尾钩子 15、竖屏视听 10、系列化潜力 5、合规 5。3 分是明显短板，6 分合格，9 分头部。最多 3 条改法，每条落到具体节拍号。

⛔ 关卡：用户确认剧本（附质量门结果和审片分）。

**上线标准（红线，任何一条不过都不能交付）**：
1. 合规：不出现血腥伤口特写和肢体残缺；不写未成年人恋爱或性暗示，校园剧角色一律成年；不美化毒品、赌博、暴力报复和霸凌；不写自杀自残的方法细节；没有低俗擦边台词和镜头；不出现真实品牌、真实在世人物和地域、民族歧视。
2. 价值观：主角的爽点不建立在违法或欺凌弱者上；反派可以坏，但剧情不认可坏。
3. 格式：时长在目标 ±15% 内；前 3 秒有看得懂的冲突或反常画面；最后一拍是悬念；台词无错别字；竖屏构图可拍。
4. 系列：本集完成分集行的主事件并落在分集钩子上；付费点集数的钩子必须是「不付费就不知道」的强悬念。


## 阶段 5　分镜（E0n/shots.csv）

列：`shot,beats,dur,size,camera,frame_cn,video_cn,lens,camera_pos,composition,eyeline,people,sound`

- beats 认领连续节拍（如 3-5），全部节拍按顺序、不重不漏，镜头不跨场次；每镜 2–8 秒，台词按 4.5 字/秒放得下；相邻镜头连续生成时一段不超过 15 秒。
- frame_cn（首帧，中文）：直呼角色名，含景别词。
- video_cn（视频，中文）：通用身份（「一名银发青年」），不写角色名；一镜一个主运镜；动作在几秒内做得完，写幅度和速度；台词逐字保留；不写画风。
- lens、camera_pos、composition、eyeline 必填；同框 ≤3 人；竖屏多用近景特写；钩子、高光、集尾镜头设计细致，过场从简；sound 只写环境声、动作声、非语言人声。字段内用全角逗号。

运行 `python3 .claude/skills/short-drama-preprod/scripts/check.py shots <剧名>/E01/script.md <剧名>/E01/shots.csv`。

⛔ 关卡：用户确认分镜，然后进入下一集。

## 工作室模式（全自动）

用户说「工作室模式」「全自动」「写到第 N 集再给我看」时使用。用户只在开头给一句话或概念、在最后看汇总报告，中间不停。

每集循环（主会话调度，按集顺序）：
1. `screenwriter` 写大纲和剧本，自跑质量门。
2. 并行调 `reviewer-platform`、`reviewer-ads`、`reviewer-audience` 三个独立审片人，再调 `continuity` 查连续性。
3. 通过条件：三人平均分 ≥ 80，任何一人 ≥ 70，没有红线，连续性没有 ✗。
4. 没通过：主会话把三份意见和连续性问题合并成最多 4 条改法（先红线、再连续性、再按扣分多少排），交给 screenwriter 重写，再审。最多 3 轮。3 轮仍没过就记进 state.md 标「未达标」，继续写下一集。
5. 每集完成后更新 state.md（分数、轮数、主要问题），每 5 集提交一次。
6. 全部写完：写 `报告.md`（每集一行：标题、三人分数、轮数、是否达标、最弱一点），导出网页 json，回复用户一句结论和报告链接。



- `screenwriter`：按本技能写一集的大纲或剧本，并自己跑质量门修到通过。
- `storyboarder`：把确认的剧本拆成 shots.csv，并跑分镜质量门。
- `reviewer`：独立审片，只读剧本和整季，不看写作过程，按短剧标准打分并给改法，写 review.md。

自动模式写多集时：主会话负责调度和 state.md；同一集内按 大纲 → 剧本 → reviewer → 分镜 的顺序；不同集之间互相依赖前情，所以默认顺序写，只有分镜可以和下一集的大纲并行。

## 停下时的回复格式

三到五句：产出了什么（链接文件）、质量门结果、审片分（剧本阶段）、最弱的一两点、需要拍板的问题（带推荐项）。然后等待。
